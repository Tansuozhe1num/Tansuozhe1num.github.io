Netty

发表于2026-09-11|更新于2026-10-11
|总字数:3k|阅读时长:13分钟|浏览量:

Netty 是 Java 后端开发中非常重要的高性能网络通信框架。尤其是你正在设计的 IM 系统，如果需要实现 WebSocket/TCP 长连接、心跳检测、消息编解码、连接管理和服务端推送，Netty 是值得深入掌握的技术。

一、Netty 是什么？

Netty 是一个基于 Java NIO 的异步事件驱动网络应用框架，可以用于构建 TCP、UDP、HTTP、WebSocket 等网络应用。

三、Netty 核心架构

Netty 最重要的四个概念是：

1. Bootstrap

启动器。客户端使用 Bootstrap，服务端使用 ServerBootstrap。

2. EventLoopGroup

管理事件循环线程，负责连接接入、网络 I/O 与任务调度。

3. Channel

表示一个网络连接或监听通道，提供读写、关闭等操作。

4. ChannelPipeline

每个连接的处理链，负责解码、业务处理、编码等步骤。

1. 服务端线程模型

BossGroup 负责接收新连接，WorkerGroup 负责已建立连接的 I/O。一个 EventLoop 通常可以处理多个 Channel，而一个已注册的 Channel 通常由固定的 EventLoop 负责处理其 I/O 事件。

最关键的原则：不要在 EventLoop 线程里执行耗时的阻塞操作。
例如，在 channelRead0() 中同步调用一个耗时的数据库查询，可能拖慢该 EventLoop 上其他连接的读写处理。

五、Handler 用法大全

Netty Handler 负责处理网络事件，是业务代码和网络框架之间的桥梁。

1. 常见回调

方法 触发时机
channelRegistered() Channel 注册到 EventLoop
channelActive() 连接激活
channelRead() 收到入站数据
channelReadComplete() 一轮读取结束
channelWritabilityChanged() Channel 可写状态变化
userEventTriggered() 收到用户事件，例如空闲事件
channelInactive() 连接断开
exceptionCaught() 传播到当前处理器的异常

在项目里，至少应该考虑连接建立、收到消息、连接关闭和异常处理这几个事件。

2. 两类最常用的入站处理器

ChannelInboundHandlerAdapter

直接接收 Object 类型消息，适合自定义复杂消息流程。

此处把 msg 传递给下一个处理器，相当于转移其后续处理责任。对于引用计数对象，不能在转交之后再随意释放它。

它默认会在 channelRead0() 返回后自动释放已接收的引用计数消息。因此，如果要把 ByteBuf 保存到异步任务中继续使用，需要正确处理引用计数和对象生命周期。

3. ChannelHandlerContext 和 Channel

  • ctx.writeAndFlush()：从当前 Handler 所在位置开始向前传播出站事件。
  • channel.writeAndFlush()：通常从 Pipeline 的尾部开始传播出站事件。
  • ctx.fireChannelRead(msg)：将入站事件传递给下一个 Handler。

如果某个编码器没有被调用，优先检查 Pipeline 中 Handler 的加入顺序，以及实际使用的是 ctx.writeAndFlush() 还是 channel.writeAndFlush()。

4. @Sharable 的含义

@Sharable 表示处理器可以被多个 Channel 共享，但只有在共享确实安全时才应使用。

不要把当前连接的用户 ID、业务请求缓存等可变状态直接存放在一个共享 Handler 的普通实例字段里。

六、心跳检测与空闲连接清理

IM 服务不能只依赖连接是否断开来判断客户端是否在线。网络切换、客户端休眠和中间代理超时都可能让连接进入异常状态。

Netty 提供 IdleStateHandler 检查读空闲、写空闲和读写均空闲的情况。

2. 心跳机制要注意什么？

TCP KeepAlive 不等于应用心跳。

TCP KeepAlive 主要由操作系统控制；业务层心跳则可以判断应用客户端是否仍能正常响应。

还要考虑移动端休眠、NAT 超时、负载均衡器连接超时，以及心跳流量和检测误判等问题。不要把读空闲事件机械地当成客户端已经离线：例如，某些客户端可能只接收推送，不定时发送业务消息。
